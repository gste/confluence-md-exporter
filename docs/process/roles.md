# Roles: AI vs human

Кто что может делать. Всё, что помечено «Human only», агент обязан трактовать как жёсткий стоп.

Файл **продукт-агностичен**. Продуктовые зоны повышенного риска объявляет пакет спецификации (`docs/spec/`), а не этот файл.

## Role map

| Роль           | Кто                                   | Основные артефакты                                                    |
|----------------|---------------------------------------|-----------------------------------------------------------------------|
| Implementer    | ИИ-агент                              | код, unit-тесты, PR по задаче                                         |
| Planner        | ИИ-агент или человек                  | README эпика, нарезка задач, job-промпт                               |
| Spec editor    | ИИ черновит, **человек мерджит**      | `docs/spec/**`                                                        |
| Decision owner | **человек**                           | `status` в `docs/decisions/**`                                        |
| Reviewer       | **человек** (ИИ может помочь сводкой) | approve и merge в default branch                                      |
| Auditor        | ИИ-агент                              | отчёт о противоречиях ADR ↔ спека, spec delta audit, заметки о рисках |
| Init author    | человек (ИИ может черновить)          | `docs/init/**` → впоследствии `docs/archive/`                         |

## AI may

- Читать любые документы; предпочитать минимальный контекст на задачу.
- Черновить текст ADR (`status: proposed`).
- Черновить правки спеки и указывать на конфликты с кодом или с ADR.
- Править `docs/spec/**` хирургически внутри объявленной Spec delta: минимум hunks, только перечисленные якоря.
- Собирать пакеты задач в `docs/todo/<epic>/` **со ссылками** на спеку, а не с дублированием закона.
- Реализовывать код и тесты для одной задачи в границах действующей спеки.
- Запускать форматтеры, линтеры и тест-раннер проекта.
- Писать сводки PR, чеклисты и перечни остаточных рисков.
- Коммитить законченный шаг без просьбы «закоммить» (см. `workflow.md`, «Agent commits»).
- Предлагать классификацию изменения (`trivial` | `spec-patch` | `adr+spec` | `epic`).

## AI must not

- Ставить ADR `status: accepted` или `rejected`.
- Мерджить в default branch (если человек не прописал явно узкую политику авто-мерджа для `trivial`).
- Менять `docs/spec/**` или `docs/decisions/**` без задачи, которая это явно разрешает.
- Трогать якоря спеки вне объявленной Spec delta и оставлять внутри `docs/spec/**` ленты `ADDED` / `MODIFIED` / `REMOVED` и формулировки «было / стало».
- Принимать дифф ветки за источник требований вместо `docs/spec/**`.
- Придумывать поведение продукта, которого нет в `docs/spec/`.
- Реализовывать из Init Requirements, чата или текста ADR без соответствующего императива в спеке.
- Расширять scope за пределы того, что действующая спецификация объявила in scope.
- Коммитить секреты и реальные креды.
- Пропускать человеческие гейты, перечисленные ниже.

## Human only

- Принимать и отклонять ADR.
- Принимать первоначальный пакет спецификации — ревью выполняется из единственной точки входа `docs/spec/README.md` — и последующие merge, меняющие контракты в `docs/spec/`.
- Одобрять merge PR, меняющих поведение, в default branch.
- Финальное слово по безопасности, кредам, границам доверия и по любым зонам, которые **спецификация** пометила как human-gated.
- Приоритеты и очерёдность эпиков.

## Human gates by change type

### `trivial`

- Человек: лёгкое ревью PR (глубина — на усмотрение команды; допустима политика авто-мерджа при зелёных тестах).
- ИИ: может открыть PR; мерджить не может, если такая политика прямо не разрешает.

### `spec-patch`

- Человек: обязан отсмотреть и одобрить изменения **спеки**, которые меняют контракты.
- ИИ: может подготовить весь PR; обязан отметить влияние на контракт в теле PR.

### `adr+spec`

- Человек: обязан принять ADR, затем одобрить отражение решения в спеке.
- ИИ: может черновить и то и другое; не имеет права считать ADR со `status: proposed` законом для кода, пока он не принят **и** не зеркалирован в спеку.

### `epic`

- Человек: одобряет README эпика (цель, порядок, границы) до массовой реализации.
- ИИ: реализует задача за задачей после этого одобрения.
- Человек: отсматривает каждый PR задачи (глубина пропорциональна риску); глубже — когда задача попадает в зоны, помеченные в `docs/spec/` как высокорисковые.

## Job `/fix-bug`

Не отдельная роль. Сессия меняет роль после human gate (черновик ADR → Implementer). Код — только когда закон уже в спеке; для `trivial` — сразу. `spec-patch`: коммит спеки, затем код в той же сессии. `adr+spec`: стоп на `accepted`. Гейты те же, что у типа изменения. Не смешивать незакоммиченные спеку и код.

## Stop-and-ask triggers (implementer)

Если посреди задачи появилось любое из этого — остановись и спроси человека, вместо молчаливого выбора:

1. Спека молчит или противоречива по нужному поведению.
2. Два пути реализации одинаково укладываются в спеку, но различаются по безопасности, риску потери данных или публичному контракту.
3. Поведение в рантайме расходится со спецификацией (зафиксируй доказательства, предложи `spec-patch`).
4. DoD задачи требует правки спеки, а текст задачи её запретил.
5. Изменение попадает в human-gated зону, объявленную в `docs/spec/` (либо в креды и границы доверия в целом).
6. Дифф спеки оказался шире объявленной Spec delta (файлы или якоря, которых никто не просил).

## AI assistance on review (allowed)

На PR агент-аудитор может опубликовать:

- сопоставление изменённых файлов с секциями спеки;
- spec delta audit: изменённые файлы и якоря спеки обязаны быть подмножеством объявленного списка `ADDED` / `MODIFIED` / `REMOVED`, лишние hunks — нарушение DoD;
- чеклист из DoD задачи;
- остаточные риски.

Кнопку approve и merge всё равно нажимает человек.

## RACI (compact)

| Активность                 | AI Implementer | AI Planner/Auditor | Человек   |
|----------------------------|----------------|--------------------|-----------|
| Черновик Init Requirements | C              | C                  | R/A       |
| Черновик ADR               | C              | R                  | A         |
| Принятие ADR               | —              | C                  | R/A       |
| Правка спецификации        | R (черновик)   | C                  | A (merge) |
| Нарезка задач эпика        | C              | R                  | A         |
| Код и тесты                | R              | C                  | A (ревью) |
| Merge в main               | —              | —                  | R/A       |

R = делает работу, A = отвечает за «да / нет», C = консультируется.

## Domain-specific sensitive zones

Этот процессный файл **не** перечисляет продуктовые горячие точки.

Если репозиторию нужны дополнительные человеческие гейты, объяви их в пакете спецификации (короткий подраздел «Review gates» / «Human-gated areas») и ссылайся на этот подраздел из DoD задач. Процесс остаётся общим, продуктовый риск остаётся в `docs/spec/`.
