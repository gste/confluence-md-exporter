# Prompt: spec-to-epic

Job prompt: нарезать принятую спецификацию на эпик и атомарные задачи под `docs/todo/<epic-id>/`.

Как использовать: вставь core prompt из [`../agent-prompt.md`](../agent-prompt.md), затем этот файл, затем назови объём работ («весь пакет», «клиент и загрузка», конкретный модуль).

Этот файл **не повторяет процесс**: контракт файла задачи, формат Spec delta, гейты и общие запреты — в `docs/process/workflow.md` и `roles.md`.

---

## 0. Preconditions

- `stage: spec-first` в `docs/process/STATUS.md`. Если `bootstrap` — стоп: сначала работа 02 и приёмка пакета человеком.
- Роль на сессию: **Planner**. Продуктовый код не пишешь, спеку не правишь.
- Секции спеки, покрывающие эпик, существуют и смерджены; открытых развилок в этой области нет (accepted ADR отражён императивом). Иначе стоп.
- В преамбуле указывай `change type: epic`.

## 1. Inputs

- `docs/spec/README.md` и только те модули, которые попадают в объём эпика.
- Раздел human-gated зон спеки: он определяет, какие задачи потребуют глубокого ревью.
- Раздел обязательств по тестам: из него берутся имена тестов для DoD задач.

Требований, которых нет в спеке, в задачах быть не может. Пробел в спеке — стоп и предложение `spec-patch`, а не «допишу в задаче».

## 2. Output

```text
docs/todo/<epic-id>/README.md
docs/todo/<epic-id>/task/NN-<slug>.md    # kind: task
docs/todo/<epic-id>/bug/NN-<slug>.md     # kind: bug
```

`README.md` эпика содержит: цель в 2-3 предложениях, что входит и что не входит, таблицы **Task** и **Bug**, ссылки на модули спеки, признак завершения эпика. Ничего из спеки в него не копируется. Пустую подпапку не создавать.

Planner обязан проставить `kind: task` или `kind: bug` (совпадает с каталогом). Для `bug` — ещё `opened: YYYY-MM-DD`.

`NN` — сквозной: прочитай [`docs/todo/README.md`](../../todo/README.md), возьми `1 + max(Closed ∪ живые task/ и bug/)`, нарежь `next`, `next+1`, …. Не начинай с `01` в новой папке. Обнови список Open в том же README. Closed и корневой `CHANGELOG.md` не трогай. После нарезки закоммить сам.

## 3. Task atomicity

Задача считается атомарной, если выполняется всё:

- один PR и один логический результат; ориентир — до ~300 строк диффа плюс тесты;
- ровно один модуль спеки является владельцем изменяемого поведения;
- DoD выражен наблюдаемыми фактами: имена тестов, затронутые файлы, поведение;
- задачу можно проверить, не читая другие задачи;
- зависимости указаны явно, порядок задач их не нарушает.

Слишком крупная задача режется по границе модуля спеки или по границе контракта, а не «по половине файла».

## 4. Task file contents

Обязательные поля — по `workflow.md`, раздел «Task file contract». Дополнительно следи за тем, чтобы:

- `kind` проставлен (`task` или `bug`) и совпадает с каталогом (`task/` / `bug/`);
- имя файла — `NN-<slug>.md` без префикса kind (номер из формулы в `docs/todo/README.md`);
- для `bug` проставлен `opened: YYYY-MM-DD`;
- ссылки шли на конкретные якоря, а не на файл целиком;
- `Spec delta` был `none` для обычных задач и заполнялся только для задач типа `spec-patch` / `adr+spec`;
- задача, затрагивающая human-gated зону, ссылалась на соответствующий раздел спеки прямо в DoD;
- DoD называет имена тестов; тексты кейсов в `docs/` не копировать ([07-testing.md#test-cases](../../spec/07-testing.md#test-cases));
- в тексте не было ни копий требований, ни альтернативных дизайнов, ни обоснований «почему так».

## 5. Stop-and-ask

- Спека молчит или противоречива в области эпика.
- В области эпика остался `OPEN DECISION` или ADR со `status: proposed`.
- Эпик целиком лежит в human-gated зоне: нужен явный приоритет и согласие человека до нарезки.
- Объём не режется на атомарные задачи без изменения контрактов: это признак недостающего `spec-patch`.

## 6. Definition of Done

- [ ] `docs/todo/<epic-id>/README.md` описывает цель, границы и порядок задач
- [ ] каждая задача атомарна по критериям [Task atomicity](#3-task-atomicity)
- [ ] каждая задача имеет `kind: task` или `kind: bug`, лежит в `task/` или `bug/`, имя `NN-<slug>.md`
- [ ] у каждой `bug`-задачи есть `opened`; в README эпика таблица Bug с колонкой `Opened`
- [ ] каждая задача ссылается на якоря спеки и содержит все обязательные поля
- [ ] задачи покрывают объём эпика без пробелов и без пересечений
- [ ] задачи в human-gated зонах помечены ссылкой на раздел гейтов
- [ ] требований вне спеки нет; текст спеки не скопирован
- [ ] продуктовый код не написан; `docs/spec/**` не изменён
- [ ] `NN` сквозной по формуле в `docs/todo/README.md`; Open обновлён; Closed и `CHANGELOG.md` не трогались
- [ ] человеку остаётся один шаг: утвердить README эпика до массовой реализации
- [ ] нарезка закоммичена агентом

В конце ответа: список файлов эпика, порядок задач с зависимостями, задачи, требующие глубокого ревью.
