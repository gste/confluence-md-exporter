# Prompt: fix-bug

Job prompt: взять **один** баг — от наблюдения или файла в `docs/todo/<epic>/bug/` — до кода. Спека сначала, код по диффу спеки.

Как использовать: вставь core prompt из [`../agent-prompt.md`](../agent-prompt.md), затем этот файл, затем наблюдение и/или путь к файлу бага.

Контракт файла, Spec delta, гейты — в `workflow.md` и `roles.md`. Новой роли нет: после human gate меняется роль сессии (Spec editor → Implementer).

---

## 0. Preconditions

- `stage: spec-first`.
- Ровно один баг на вызов. Пачка наблюдений — отдельные вызовы (или сначала 03, потом по одному).
- Путь в `task/` или `kind: task` — стоп: это работа 04.
- В преамбуле: `kind: bug`, change type после сверки со спекой, якоря, гейты.
- Ветка кода: `bugfix/<slug>`.

## 1. Inbox

Нет файла — создай `docs/todo/<epic>/bug/NN-<slug>.md`: `NN` из формулы в `docs/todo/README.md` (эпик с README, если его нет; пустой `task/` не создавать; Closed не трогать, пока баг открыт). Есть файл — не пересоздавай, продолжай с текущего шага.

Поля — контракт `kind: bug` в `workflow.md`. `## Run` без секретов, тел страниц, живых URL с кредами.

## 2. Classify (действующий императив, не желаемый фикс)

| Наблюдение vs спека | Change type | Дальше |
|---------------------|-------------|--------|
| спека права, код уехал | `trivial` | сразу код; спеку не трогать |
| молчит или врёт, развилка очевидна | `spec-patch` | дельта → спека → **коммит** → код (без стопа на ревью коммита) |
| два рабочих варианта | `adr+spec` | ADR `proposed` → **коммит** → **стоп** (`accepted` ставит человек) → дельта и зеркало в спеке → **коммит** → код |
| поведение уже в спеке (в т.ч. out of scope) | не баг | стоп, не чинить |

Прогон — только если без него нельзя выбрать строку таблицы. Живой Confluence не обязателен.

## 3. Spec then code

Не держать незакоммиченные спеку и код в одном дереве. Не писать код из ADR `proposed` и не писать код, пока спека `spec-patch` / `adr+spec` не в законе.

После того как закон в спеке (или сразу при `trivial`): тесты слайса **до** кода — прогон на текущей реализации должен быть красным для этого поведения. Уже зелёные — стоп. Затем минимальный код до зелёных тестов. Операторский контур — как в работе 04 (`README.md` или `README unchanged`). Красные тесты не коммитить. Каждый законченный шаг закоммить сам.

## 4. PR and inbox

Тело PR — как в работе 04, плюс ссылка на файл бага (пока он есть в диффе удаления).

В том же PR:

1. удалить файл из `bug/`;
2. убрать строку из таблицы Bug в README эпика;
3. дописать Closed в `docs/todo/README.md` и пункт в `CHANGELOG.md` → `## Unreleased`;
4. если слайсов в `task/` и `bug/` не осталось — удалить `docs/todo/<epic>/` и убрать эпик из Open.

Мердж делает человек.

## 5. Definition of Done

- [ ] классификация записана; не-баг не чинился
- [ ] для `adr+spec`: код только после `accepted` и зеркала в спеке
- [ ] для `spec-patch` / `adr+spec`: `git diff -- docs/spec/` ⊂ объявленной дельты; changelog-лент нет
- [ ] DoD файла закрыт наблюдаемыми фактами
- [ ] тесты слайса сначала не прошли на коде до фикса, затем зелёные
- [ ] секретов нет
- [ ] файл бага удалён в этом PR; Closed и Unreleased в `CHANGELOG.md` дополнены; эпик снесён, если очередь пуста
- [ ] если `docs/spec/**` не менялся — в ответе явно `spec unchanged`
- [ ] в default branch ничего не смерджено

В конце ответа по-русски: что сделано, чем подтверждено, какой гейт у человека. Если `docs/spec/**` не менялся — отдельной фразой `spec unchanged`. Если человек в этом ходе пишет по-английски — ответ на EN.
