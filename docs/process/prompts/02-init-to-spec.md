# Prompt: init-to-spec

Job prompt для одной работы: превратить Init Requirements в модульный пакет спецификации под `docs/spec/`.

Как использовать: вставь core prompt из [`../agent-prompt.md`](../agent-prompt.md), затем этот файл, затем укажи `docs/init/**`. В GUI то же самое делает `/init-to-spec`.

Этот файл **не повторяет процесс**. Роль, стадия, порядок чтения, типы изменений, общие запреты, stop-and-ask, формат преамбулы — в `AGENTS.md` и `docs/process/**`. Здесь только то, что специфично для сборки пакета.

---

## 0. Preconditions

- `stage: bootstrap` в `docs/process/STATUS.md`. Если `spec-first` — стоп: пакет уже принят, изменения идут как `spec-patch`, а не как сборка.
- `docs/init/` существует и непуст. Пусто или нет файла — stop-and-ask, продукт не выдумывать.
- Роль на сессию: **Spec editor (draft)**. Не Implementer, не нарезка эпиков (это другой промпт).
- Это одноразовая bootstrap-последовательность (`docs/process/workflow.md`), а не один из четырёх change type. В преамбуле указывай `change type: bootstrap (spec pack draft)`.

## 1. Inputs

- Смысл берётся только из `docs/init/**` и ADR со `status: accepted`.
- ADR со `status: proposed` законом не является: развилку сам не закрываешь.
- Требований, которых нет в этих двух источниках, в пакете быть не может.

## 2. Output: modular pack

```text
docs/spec/README.md          # единственная точка входа и приёмки
docs/spec/00-context.md      # цели, in scope, out of scope, акторы, ограничения
docs/spec/<NN>-<slug>.md     # один bounded context = один файл
```

Обязательные разделы пакета — без них процесс теряет опору:

- **Границы**: положительный список in scope и список out of scope. На него опирается запрет расширения области из `AGENTS.md`.
- **Human-gated зоны**: перечень продуктовых областей, изменение которых требует одобрения человека независимо от размера диффа. `docs/process/roles.md` намеренно их не перечисляет и делегирует спеке; на этот раздел ссылаются DoD задач.
- **Обязательства по тестам**: что обязано быть покрыто. На «testing section of the Specification» ссылаются DoD в `AGENTS.md` и `workflow.md`.
- **По одному файлу на контекст**: контракты данных, конфигурация, интеграции, оркестрация, NFR и прочее по природе продукта.

Правила нарезки:

- один контекст — один файл; ориентир ≤ 400 строк, крупный алгоритм выносится в подфайл, а не в простыню;
- имена файлов, заголовки, якоря, ID, идентификаторы кода — английские; проза — язык Init;
- **якоря стабильны**: на них ссылаются задачи и Spec delta, переименование якоря само является `MODIFIED` / `REMOVED`;
- каждая норма — императив о том, как система устроена сейчас; ни «на усмотрение», ни «возможно», ни двух равноправных дизайнов;
- **пакет самодостаточен**: ни одной ссылки на `docs/init/**` как на источник нормы — после приёмки Init необязывающий, такая ссылка станет висячей;
- «почему» не переносится: обоснования живут в `docs/decisions/`, в спеке только следствие;
- Init не копируется целиком: он сжимается в контекст, детали поведения расходятся по модулям;
- DeltaFuse в спеку не копируется, достаточно ссылки.

## 3. Spec README as the single acceptance entry

Человек принимает пакет только отсюда. Второго входа не создавать: ни `ACCEPTANCE.md`, ни summary, ни review-notes, ни «краткая версия для чтения».

Обязательное содержимое, компактно (ориентир ≤ 150 строк):

- law reminder: реализация читает только этот пакет;
- **TOC**: все модули со ссылками и одной строкой назначения каждого;
- **review tour**: порядок чтения для приёмки — что открыть первым и что именно проверить в каждом модуле;
- **coverage**: каждое требование Init → модуль, либо `out of scope`, либо `OPEN DECISION`. Без этой таблицы DoD ниже нечем проверить;
- сознательные отклонения от Init с обоснованием в одну строку;
- список `OPEN DECISION` со ссылками на черновики ADR;
- указатель на раздел human-gated зон.

Блоки coverage и отклонений историчны: после приёмки их можно перенести в `docs/archive/`, TOC и review tour остаются.

## 4. OPEN DECISION

Развилка, которую не закрывает accepted ADR:

- выбор не делаешь;
- ставишь пометку в месте нормы и запись в README;
- заводишь черновик `docs/decisions/NNNN-<slug>.md` со `status: proposed`;
- модуль с `OPEN DECISION` не является законом для реализации, пока ADR не принят и не отражён императивом (`workflow.md`, `adr+spec`);
- остальной пакет из-за этого не блокируется.

## 5. Legacy SDD.md

Монолит и пакет не могут сосуществовать: это два закона в одной папке. В том же изменении:

- перенеси в модули то, что подтверждено Init и accepted ADR;
- удали файл (запись `REMOVED` в манифесте) либо перенеси в `docs/archive/`;
- не оставляй «переходную» ссылку на монолит из README.

## 6. Change manifest

- Пакет собирается с нуля — манифест равен списку созданных файлов.
- Пакет частично существует — заявляешь `ADDED` / `MODIFIED` / `REMOVED` с якорями (формат в `workflow.md`, раздел Spec delta), правишь только эти места, нетронутые главы не переписываешь «для красоты».
- Манифест живёт в ответе и в теле PR. Внутрь глав спеки он не попадает.

## 7. Stop-and-ask

- Init внутренне противоречив.
- Init требует поведения, которое нельзя выразить императивом без догадки.
- Напрашивается удаление целого существующего модуля спеки без явной команды человека.
- `OPEN DECISION` попадает в human-gated зону.

## 8. Definition of Done

- [ ] `docs/spec/README.md` работает как единственная точка приёмки: TOC, review tour, coverage, OPEN DECISION, указатель на human-gated зоны
- [ ] каждое требование Init отражено в модуле, объявлено out of scope или числится `OPEN DECISION`
- [ ] accepted ADR отражены императивом, без «см. варианты в ADR»
- [ ] есть раздел границ, раздел human-gated зон и раздел обязательств по тестам
- [ ] нет ссылок на `docs/init` как на норму, нет changelog-лент, нет обоснований «почему» внутри глав
- [ ] `docs/spec/SDD.md` в пакете больше нет
- [ ] нет продуктового кода и нет `docs/todo/`
- [ ] `STATUS.md` не переключён: флип на `spec-first` делает человек
- [ ] человеку остаётся один gate — принять пакет

В конце ответа: манифест файлов, список `OPEN DECISION`, что человеку проверить перед accept.
