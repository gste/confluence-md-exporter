# Prompt: implement-task

Job prompt: реализовать один файл задачи из `docs/todo/<epic>/` и открыть PR.

Как использовать: вставь core prompt из [`../agent-prompt.md`](../agent-prompt.md), затем этот файл, затем укажи путь к файлу задачи.

Этот файл **не повторяет процесс**: роль, минимальный контекст, преамбула, запреты, гейты и stop-and-ask — в `AGENTS.md` и `docs/process/**`.

---

## 0. Preconditions

- `stage: spec-first` в `docs/process/STATUS.md`.
- Указан конкретный файл задачи. Файла нет — ты не Implementer: либо работа 03, либо стоп.
- Роль на сессию: **Implementer**. ADR не пишешь, эпики не открываешь.
- В преамбуле указывай тип из задачи (`trivial` | `spec-patch` | `adr+spec`) и якоря спеки, перечисленные в задаче.

## 1. Work order

1. Прочитай файл задачи целиком, затем **только** перечисленные в нём якоря спеки.
2. Выпиши для себя DoD задачи как чеклист: по нему будешь себя проверять, а не по общему впечатлению.
3. Реализуй минимальное изменение, закрывающее DoD. Ничего «заодно»: рефакторинг вне задачи, переименования, попутные улучшения тестов — отдельные задачи.
4. Тесты пиши вместе с кодом. Состав берётся из DoD задачи и раздела обязательств по тестам спеки; имена тестов из DoD должны существовать по факту.
5. Прогони инструменты качества, которые объявила спека (форматтер, линтер, типизация, тесты). Команды берутся из спеки, а не из привычки.
6. Если задача разрешает правки спеки: меняй только якоря из объявленной Spec delta, формулируй их так, будто требование всегда было таким, затем сверь `git diff -- docs/spec/` с этим списком. Лишнее откатывается или эскалируется.

## 2. Signs the task is going wrong

- Появилась необходимость решить продуктовый вопрос, которого нет в спеке.
- Диффу нужны файлы, не упомянутые ни в задаче, ни в её Spec delta.
- Тест приходится ослаблять или удалять, чтобы код прошёл.
- Реализация требует «временного» обхода: заглушки в обход контракта, отключённой проверки, захардкоженного значения вместо конфигурации.

Любой из признаков — стоп и вопрос человеку. Молча выбирать нельзя.

## 3. PR

Тело PR содержит:

- цель одной фразой и ссылку на файл задачи;
- цитаты путей и якорей `docs/spec/...` по каждому изменению поведения;
- `Spec delta` (`ADDED` / `MODIFIED` / `REMOVED` + якоря), если `docs/spec/**` менялся, иначе `none`;
- чеклист DoD задачи с отметками;
- остаточные риски и то, что сознательно не сделано.

Один таск — один PR. Мердж делает человек.

## 4. Definition of Done

- [ ] DoD задачи закрыт полностью, каждый пункт подтверждён наблюдаемым фактом
- [ ] тесты из задачи и из раздела обязательств спеки существуют и зелёные
- [ ] линтер и проверка типов, объявленные спекой, зелёные
- [ ] изменения не выходят за границы задачи; попутных правок нет
- [ ] при правках спеки: `git diff -- docs/spec/` является подмножеством объявленной Spec delta, changelog-лент внутри глав нет
- [ ] секретов в коде, логах, фикстурах и коммитах нет
- [ ] PR оформлен по [PR](#3-pr); в default branch ничего не смерджено и не запушено
- [ ] если это последний таск эпика — указано, что `docs/todo/<epic>/` пора очистить

В конце ответа: что сделано, чем подтверждено, что осталось человеку.
