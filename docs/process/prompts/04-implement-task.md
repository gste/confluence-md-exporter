# Prompt: implement-task

Job prompt: реализовать один файл из `docs/todo/<epic>/task/` и открыть PR.

Как использовать: вставь core prompt из [`../agent-prompt.md`](../agent-prompt.md), затем этот файл, затем укажи путь к файлу.

Этот файл **не повторяет процесс**: роль, минимальный контекст, преамбула, запреты, гейты и stop-and-ask — в `AGENTS.md` и `docs/process/**`.

---

## 0. Preconditions

- `stage: spec-first` в `docs/process/STATUS.md`.
- Указан файл в `docs/todo/<epic>/task/`. Файла нет — ты не Implementer: либо работа 03, либо стоп.
- Путь в `bug/` или `kind: bug` — стоп: это работа 05 (`/fix-bug`).
- Роль на сессию: **Implementer**. ADR не пишешь, эпики не открываешь.
- В преамбуле указывай `kind: task`, тип изменения (`trivial` | `spec-patch` | `adr+spec`) и якоря спеки из файла.
- Ветка: `feature/<slug>`. Git-префикс `task/` не использовать.

## 1. Work order

1. Прочитай файл задачи целиком, затем **только** перечисленные в нём якоря спеки.
2. Выпиши для себя DoD задачи как чеклист: по нему будешь себя проверять, а не по общему впечатлению.
3. Если задача разрешает правки спеки: меняй только якоря дельты, формулируй как будто так было всегда, сверь `git diff -- docs/spec/` со списком, закоммить спеку. Затем тесты и код.
4. Тесты слайса — **до** кода. Состав: DoD задачи и обязательства спеки; имена из DoD должны существовать. Прогони их на текущей реализации: они **не должны** пройти для поведения этого слайса. Уже зелёные — стоп: тесты не фиксируют изменение, либо работа уже сделана.
5. Затем минимальный код, пока эти тесты не станут зелёными. Ничего «заодно».
6. Прогони инструменты качества, которые объявила спека (форматтер, линтер, типизация, тесты). Команды берутся из спеки, а не из привычки.
7. Если изменился операторский контур (CLI, env-ключи, входной файл, коды выхода, layout выгрузки, форма `run_report` / `manifest`) — хирургически обнови корневой `README.md`. Это часть задачи, не drive-by. Не копируй главы спеки: команды, пути, обязательные ключи и ссылка на `docs/spec/`. Секреты и реальные URL инстанса не класть. Если контур не менялся — в конце ответа явно `README unchanged`.
8. В том же PR удали закрытый файл из `task/` и строку таблицы Task в README эпика. Допиши Closed в `docs/todo/README.md` и пункт в `CHANGELOG.md` под `## Unreleased` (`- NN краткая фраза`). Если в `task/` и `bug/` слайсов не осталось — удали `docs/todo/<epic>/` и убери эпик из Open.
9. Каждый законченный шаг закоммить сам (спека отдельно от кода). Не жди «закоммить».

## 2. Signs the task is going wrong

- Появилась необходимость решить продуктовый вопрос, которого нет в спеке.
- Диффу нужны файлы, не упомянутые ни в задаче, ни в её Spec delta.
- Тест приходится ослаблять или удалять, чтобы код прошёл.
- Новые тесты слайса уже зелёные до правки кода — они не фиксируют изменение.
- Реализация требует «временного» обхода: заглушки в обход контракта, отключённой проверки, захардкоженного значения вместо конфигурации.

Любой из признаков — стоп и вопрос человеку. Молча выбирать нельзя.

## 3. PR

Тело PR содержит:

- цель одной фразой и ссылку на файл задачи;
- цитаты путей и якорей `docs/spec/...` по каждому изменению поведения;
- `Spec delta` (`ADDED` / `MODIFIED` / `REMOVED` + якоря), если `docs/spec/**` менялся, иначе `none`;
- чеклист DoD задачи с отметками;
- остаточные риски и то, что сознательно не сделано.

Один таск — один PR. Мердж делает человек.

## 4. Definition of Done

- [ ] DoD задачи закрыт полностью, каждый пункт подтверждён наблюдаемым фактом
- [ ] тесты слайса сначала не прошли на коде до фикса, затем зелёные; имена из DoD существуют
- [ ] линтер и проверка типов, объявленные спекой, зелёные
- [ ] изменения не выходят за границы задачи; попутных правок нет
- [ ] при правках спеки: `git diff -- docs/spec/` является подмножеством объявленной Spec delta, changelog-лент внутри глав нет
- [ ] секретов в коде, логах, фикстурах и коммитах нет
- [ ] PR оформлен по [PR](#3-pr); в default branch ничего не смерджено и не запушено
- [ ] корневой `README.md` обновлён при смене операторского контура, иначе в ответе `README unchanged`
- [ ] если `docs/spec/**` не менялся — в ответе явно `spec unchanged`
- [ ] закрытый файл удалён из `task/`; строка README эпика убрана; Closed и Unreleased в `CHANGELOG.md` дополнены; пустой эпик снесён

В конце ответа по-русски: что сделано, чем подтверждено, что осталось человеку. Если `docs/spec/**` не менялся — отдельной фразой `spec unchanged`. Имена файлов, якоря и термины процесса не переводить. Если человек в этом ходе пишет по-английски — ответ на EN.
