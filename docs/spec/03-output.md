# Output contracts

Навязанный контракт выгрузки: layout, bronze, gold Markdown, каталог, отчёт, имена файлов. Потребители читают эти файлы; другая схема путей запрещена.

## Layout

Корень — `EXPORT_OUTPUT_DIR` (default `output`):

```text
output/
├── 01_raw/<page_id>.json
├── 01_raw/<page_id>.assets.json
├── 02_interim/<page_id>.html
├── 03_assets/<page_id>/<safe_filename>
├── 04_markdown/<page_id>_<slug>.md
├── 04_markdown/manifest.json
└── run_report.json
```

Каноническая относительная ссылка на медиа из Markdown:

```text
../03_assets/<page_id>/<safe_filename>
```

Другая схема путей (`../assets/...` и аналоги) запрещена: из каталога `04_markdown/` она не резолвится в `03_assets/`.

`page_id` во всех именах и полях — строка десятичных цифр.

## Bronze

`01_raw/<page_id>.json` хранит как минимум перечисленные ключи. Поля можно расширять; перечисленные ключи стабильны.

| Ключ | Смысл |
|---|---|
| `page_id` | строка |
| `edition` | всегда `datacenter` |
| `title` | заголовок страницы; HTML-entities декодированы |
| `space_key` | ключ пространства |
| `version` | номер текущей версии страницы, целое |
| `status` | статус контента в Confluence (`current` и т.п.) |
| `created_by` | идентификатор или display name создателя, как отдаёт API |
| `updated_at` | время обновления версии, ISO-8601 |
| `source_url` | абсолютный URL страницы на инстансе |
| `labels` | массив строк (имена меток) |
| `ancestors` | массив объектов `{ "id", "title" }` от корня к родителю |
| `body_storage` | тело именно в Storage Format |
| `attachments` | массив: `id`, `title`, `media_type`, `file_size`, `download_path` (REST-путь или URL скачивания) |
| `fetched_at` | время выгрузки, ISO-8601 |

`source_url` строится так: если REST отдал относительный `_links.webui`, он склеивается с `CONFLUENCE_BASE_URL`; если `webui` уже абсолютный — используется как есть; если `webui` нет — `{CONFLUENCE_BASE_URL}/pages/viewpage.action?pageId={page_id}`.

Тело в `view` / `export_view` / `atlas_doc_format` не сохраняется и не запрашивается.

## Asset sidecar

Для страницы с вложениями рядом с raw лежит `01_raw/<page_id>.assets.json`: объект-карта `original → safe`, где `original` — исходное имя файла в Confluence, `safe` — имя на диске. В Markdown попадают только безопасные имена. Если вложений нет, sidecar допускается не создавать.

## Interim

`02_interim/<page_id>.html` — тело страницы после нормализации макросов `ac:*` / `ri:*` и до сборки GFM. Это промежуточный артефакт конвейера, не публичный контракт для RAG; его отсутствие у `skipped` страницы не ошибка.

## Gold Markdown

Файл `04_markdown/<page_id>_<slug>.md`. Тело — GFM. YAML frontmatter содержит обязательные ключи:

| Ключ | Смысл |
|---|---|
| `id` | строка, тот же `page_id` |
| `title` | как в bronze |
| `space_key` | как в bronze |
| `version` | как в bronze |
| `status` | как в bronze |
| `created_by` | как в bronze |
| `updated_at` | как в bronze |
| `source_url` | как в bronze |
| `labels` | как в bronze |
| `breadcrumbs` | массив title: предки по порядку + текущий title |
| `attachments_count` | число вложений, выгруженных для страницы |
| `unsupported_macros` | массив имён макросов, ушедших в fallback |

Ключи frontmatter стабильны. Тело после frontmatter соответствует [05-transform.md](./05-transform.md).

## Manifest

`04_markdown/manifest.json` — JSON-массив записей. Невалидные URL в манифест не входят.

| Ключ | Смысл |
|---|---|
| `id` | строка `page_id`, либо `null` если id не получен (display-URL без найденной страницы) |
| `title` | заголовок, если известен, иначе `null` |
| `space_key` | если известен, иначе `null` |
| `version` | если известен, иначе `null` |
| `source_url` | если известен, иначе `null` |
| `md_path` | относительный от корня выгрузки путь к `.md`, либо `null` |
| `assets_dir` | относительный от корня путь `03_assets/<page_id>`, либо `null` |
| `labels` | массив строк, либо `[]` |
| `status` | `ok` \| `failed` \| `skipped` |
| `error` | строка причины или `null` |

## Run report

`run_report.json` в корне выгрузки:

| Ключ | Смысл |
|---|---|
| `started_at` | ISO-8601 |
| `finished_at` | ISO-8601 |
| `pages_total` | число уникальных валидных `page_id` после дедупликации |
| `ok` | число страниц `ok` |
| `failed` | число страниц `failed` |
| `skipped` | число страниц `skipped` |
| `invalid_urls` | массив объектов `{ "url", "reason" }`: исходная отклонённая строка и код причины из [02-input.md#rejection-reasons](./02-input.md#rejection-reasons) |
| `force_refresh` | значение флага этого запуска |
| `errors` | массив `{ "page_id", "error" }` по страницам `failed` (и `skipped` с причиной, если причина есть); `page_id` допускается `null` |

## Page status

| Статус | Смысл |
|---|---|
| `ok` | страница выгружена и Markdown записан в этом запуске |
| `skipped` | disk-skip, либо страница недоступна как 404 / `trashed`, либо display-URL не нашёл страницу |
| `failed` | страница не обработана из-за ошибки (403 `forbidden`, битое тело, неподдерживаемый тип, сеть после исчерпания ретраев, IO) |

404 и `trashed` не переводят страницу в `failed`: запись в отчёт и `skipped`. HTTP `403` по странице — `failed` с причиной `forbidden`, без ретраев.

## Slug

`slug` считается из title страницы после декодирования HTML-entities:

1. NFKC, затем нижний регистр.
2. Каждый символ кириллицы заменяется по таблице ниже; неизвестная кириллица отбрасывается.
3. Пробелы и пунктуация заменяются на `-`.
4. Остаются только `[a-z0-9-]`.
5. Повторяющиеся `-` сжимаются; `-` по краям снимаются.
6. Обрезка до 60 символов; если после обрезки хвост — `-`, он снимается.
7. Пустой результат → `page`.

Кириллица в имени файла Markdown не допускается: шаг 2 обязателен.

## Safe filename

Имя файла вложения на диске:

1. NFKC.
2. Разделители пути и зарезервированные для Windows символы `<>:"/\|?*` и управляющие символы заменяются на `_`.
3. Пробелы сжимаются до одного `_`.
4. Хвостовые пробелы и точки снимаются.
5. Расширение (последний суффикс после `.`) сохраняется, если оно состоит из `[A-Za-z0-9]+` длиной 1–8; иначе считается, что расширения нет.
6. Пустой basename → `file`.
7. Кириллица и прочие не-ASCII в имени вложения транслитерируются той же таблицей, что slug; остаток вне `[A-Za-z0-9._-]` заменяется на `_`.

Если два разных `original` на одной странице дают один `safe`, второму и следующим добавляется суффикс `_2`, `_3`, … перед расширением. Карта в sidecar отражает итог.

Две версии одного вложения с одним именем: на диск берётся только current.
