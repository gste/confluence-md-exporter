# Input and URL resolution

Единственный вход первой версии — текстовый список URL. Других входов нет.

## Input file

Путь по умолчанию — `input/urls.txt`, переопределяется `EXPORT_INPUT_FILE` / `--input`.

Файл — UTF-8, одна запись на строку. Пустые строки и строки, у которых первый непробельный символ — `#`, игнорируются и в отчёт не входят.

Отсутствующий файл — невозможный старт, код выхода `2`. Файл из одних пустых строк и комментариев — допустимый запуск: `pages_total` равен 0, `manifest.json` — пустой массив, код выхода `0`.

## Accepted URL forms

Перед сопоставлением база приложения нормализуется: без завершающего `/`, без `/wiki`. Если база не задана явно, она выводится из абсолютных URL списка ([#base-url-inference](#base-url-inference)). Абсолютный URL валиден только если он лежит на этой базе (тот же origin и путь начинается с контекст-пути базы, если путь базы не пуст). Совпадения одного origin недостаточно: `{origin}/pages/...` при базе `{origin}/confluence` — невалидная строка.

Допустимые формы относительно базы приложения:

1. `.../pages/viewpage.action?pageId=<id>`
2. то же с дополнительными query-параметрами (`src=` и аналоги); `pageId` берётся из query
3. `.../display/SPACE/Page+Title`
4. `.../wiki/spaces/SPACE/pages/<id>/Title`
5. `.../wiki/spaces/~user/pages/<id>/Title`
6. голая числовая строка `pageId` (только цифры, без пробелов)

Строка может быть абсолютным URL или путём, начинающимся с `/`. Путь от `/` сначала становится абсолютным от origin, затем проверяется принадлежность базе.

Форма 3 резолвится в `page_id` запросом к REST: страница типа `page` в пространстве `SPACE` с заголовком, полученным декодированием сегмента (`+` и percent-encoding). Если такой страницы нет — это не «невалидный URL»: в манифесте `id` равен `null`, `space_key` и `title` берутся из URL, статус `skipped` (эквивалент 404).

Формы 1, 2, 4, 5 и 6 дают `page_id` без поискового запроса. Сегмент Title в формах 4–5 на резолв не влияет.

## Base URL inference

Если `--base-url` / `CONFLUENCE_BASE_URL` не заданы, база выводится из абсолютных URL входного файла.

Для каждой непустой не-комментарной строки, которая является абсолютным `http`/`https` URL, процесс ищет в пути первое вхождение маркера допустимой формы: `/pages/viewpage.action`, `/pages/diffpagesbyversion.action`, `/display/`, `/wiki/spaces/`. Префикс пути до маркера — контекст-путь. База = origin + контекст-путь без завершающего `/`. Сегмент `wiki` в контекст-пути запрещён: такая строка в вывод базы не идёт.

Голые `pageId` и пути от `/` базу не дают. Строки, в которых маркер не найден, базу не дают.

Все успешно выведенные базы запуска должны совпасть. Разные origin или разные контекст-пути — невозможный старт, код выхода `2`. Ни одной выведенной базы (список из голых id, относительных путей, комментариев или нераспознанных форм) — невозможный старт, код выхода `2`, пока база не задана явно.

## Rejected forms

Любая строка, которая не совпала ни с одной формой выше, — невалидная. В том числе tiny-link `/x/<hash>` и прочие формы вне списка. Такой строке назначается ровно один код причины из [rejection-reasons](#rejection-reasons).

Невалидная строка не валит батч: она попадает в `run_report.json` как элемент `invalid_urls` (объект `{ "url", "reason" }`) и не входит в `manifest.json`.

## Rejection reasons

Код причины стабилен. Строке назначается ровно один код — первое совпавшее правило:

1. Строку нельзя превратить в абсолютный URL (нет схемы `http`/`https` и она не начинается с `/`) — `unrecognized_form`. Голый `pageId` сюда не относится: это принятая форма.
2. Origin после нормализации не совпадает с `CONFLUENCE_BASE_URL` — `origin_mismatch`.
3. Путь опознан как семейство допустимой формы, но обязательная часть отсутствует или неверна: у `viewpage.action` нет ровно одного числового `pageId`; у display пустые space или title — `malformed`.
4. Путь — tiny-link `/x/<hash>` (допускается префикс каталога перед `/x/`) либо содержит `tinyurl.action` — `tiny_link`.
5. Иное — `unrecognized_form`.

| Код | Смысл |
|---|---|
| `tiny_link` | tiny-link; в `page_id` не резолвится |
| `origin_mismatch` | чужой origin |
| `malformed` | опознанное семейство формы без обязательной части |
| `unrecognized_form` | не URL, либо форма вне [accepted-url-forms](#accepted-url-forms) |

## Deduplication

После резолва дубликаты одного и того же `page_id` (в том числе пришедшие разными формами URL) схлопываются в одну страницу батча. О схлопывании пишется предупреждение в лог. В `pages_total` дубликат считается один раз.

## Page type

В батч входят только страницы типа `page`. Если REST вернул контент иного типа, страница получает статус `failed` с причиной `unsupported_content_type` и не пишется как Markdown.
