# Input and URL resolution

Единственный вход первой версии — текстовый список URL. Других входов нет.

## Input file

Путь по умолчанию — `input/urls.txt`, переопределяется `EXPORT_INPUT_FILE` / `--input`.

Файл — UTF-8, одна запись на строку. Пустые строки и строки, у которых первый непробельный символ — `#`, игнорируются и в отчёт не входят.

Отсутствующий файл — невозможный старт, код выхода `2`. Файл из одних пустых строк и комментариев — допустимый запуск: `pages_total` равен 0, `manifest.json` — пустой массив, код выхода `0`.

## Accepted URL forms

Перед сопоставлением origin нормализуется так же, как `CONFLUENCE_BASE_URL`: без хвоста `/wiki`, без завершающего `/`. Абсолютный URL, чей origin после нормализации не совпадает с `CONFLUENCE_BASE_URL`, — невалидная строка.

Допустимые формы:

1. `.../pages/viewpage.action?pageId=<id>`
2. то же с дополнительными query-параметрами (`src=` и аналоги); `pageId` берётся из query
3. `.../display/SPACE/Page+Title`
4. `.../wiki/spaces/SPACE/pages/<id>/Title`
5. `.../wiki/spaces/~user/pages/<id>/Title`
6. голая числовая строка `pageId` (только цифры, без пробелов)

Строка может быть абсолютным URL или путём, начинающимся с `/`; путь резолвится относительно `CONFLUENCE_BASE_URL`.

Форма 3 резолвится в `page_id` запросом к REST: страница типа `page` в пространстве `SPACE` с заголовком, полученным декодированием сегмента (`+` и percent-encoding). Если такой страницы нет — это не «невалидный URL»: в манифесте `id` равен `null`, `space_key` и `title` берутся из URL, статус `skipped` (эквивалент 404).

Формы 1, 2, 4, 5 и 6 дают `page_id` без поискового запроса. Сегмент Title в формах 4–5 на резолв не влияет.

## Rejected forms

Любая строка, которая не совпала ни с одной формой выше, — невалидная. В том числе tiny-link `/x/<hash>` и прочие формы вне списка.

Невалидная строка не валит батч: она попадает в `run_report.json` как элемент `invalid_urls` и не входит в `manifest.json`.

## Deduplication

После резолва дубликаты одного и того же `page_id` (в том числе пришедшие разными формами URL) схлопываются в одну страницу батча. О схлопывании пишется предупреждение в лог. В `pages_total` дубликат считается один раз.

## Page type

В батч входят только страницы типа `page`. Если REST вернул контент иного типа, страница получает статус `failed` с причиной `unsupported_content_type` и не пишется как Markdown.
