# Context and boundaries

Продукт `confluence-md-exporter`: локальный read-only конвейер, который по списку URL забирает страницы Confluence Server/Data Center в Markdown с YAML-метаданными, локальными медиа и машинно-читаемым каталогом батча.

Реализация читает только `docs/spec/`. Правила работы агентов и людей — [`AGENTS.md`](../../AGENTS.md) и [`docs/process/`](../process/README.md); этот пакет их не дублирует.

## Problem

Корпоративная документация живёт в Confluence Server/Data Center. Её нужно регулярно забирать в Markdown-хранилище (Obsidian) и в последующие RAG/LLM-пайплайны.

Штатный экспорт Confluence (PDF, HTML, Word) для этой задачи не годится: теряются макросы, ломаются ссылки на вложения, нет устойчивых идентификаторов и меток, повторный запуск не идемпотентен.

## What the system does

1. Читает текстовый список URL страниц.
2. Резолвит каждую распознанную строку в `page_id`.
3. Выгружает metadata и тело в Storage Format, вложения и встроенные медиа.
4. Нормализует макросы `ac:*` / `ri:*` и собирает GFM Markdown с YAML frontmatter.
5. Пишет четыре выходных слоя, каталог батча и отчёт запуска.
6. Печатает прогресс выгрузки в консоль: старт, каждая страница, сводка.

Конвейер только читает Confluence. Обратно ничего не пишет.

## Goals

Каждая цель опровергается наблюдением на реальном или фикстурном прогоне.

| ID | Цель | Признак успеха |
|---|---|---|
| G-1 | Выгрузить заданный список страниц `page` из Confluence Server/Data Center | Для каждой валидной страницы, которую инстанс отдал, есть Markdown, медиа (если были) и запись в каталоге |
| G-2 | Сохранить пригодность для Obsidian и RAG | У каждой успешной страницы есть стабильный `id`, `source_url`, labels, путь к `.md` и к каталогу медиа |
| G-3 | Не портить уже актуальный локальный снимок | Повторный запуск без явной перевыгрузки на неизменённых страницах не перезаписывает актуальные медиа и Markdown |
| G-4 | Изолировать ошибки по страницам | Страница с 403, 404 или битым телом не останавливает остальные; причина видна в отчёте запуска |
| G-5 | Не терять неизвестные макросы молча и не валить из‑за них батч | Неизвестный макрос оставляет в теле след с именем макроса и извлечённым текстом; страница не переходит в `failed` только из‑за этого |
| G-6 | Дать оператору сводку в консоли | На запуск видны старт, прогресс каждой страницы и итог `ok` / `failed` / `skipped` / `invalid_urls`; подробности — в `run_report.json` |

## Actors

Единственный оператор первой версии — инженер на своей машине, с доступом в Confluence. Отдельного сервиса, UI продукта и роли «конечный читатель Confluence» нет.

Основной сценарий: оператор кладёт список URL во входной файл, задаёт доступ к инстансу через окружение, запускает конвейер локально, забирает Markdown, медиа и каталог из выходного каталога.

Повторный запуск на том же списке — штатный режим актуализации. Оператор включает полную перевыгрузку только явно.

Потребители результата (не операторы): Obsidian-хранилище и внешние RAG/LLM-пайплайны. Они читают Markdown, frontmatter, пути к медиа и каталог батча; обратно в Confluence ничего не пишут.

## In scope

Первая версия обязана уметь ровно это. Расширение границ без изменения этого раздела запрещено.

- Только Confluence Server/Data Center.
- Только страницы типа `page`.
- Единственный вход — текстовый список URL; допустимые формы — [02-input.md#accepted-url-forms](./02-input.md#accepted-url-forms).
- Выгрузка metadata + тела в Storage Format, вложений и встроенных медиа, нормализация макросов `ac:*` / `ri:*`, сборка GFM Markdown с YAML frontmatter.
- Четыре выходных слоя под корнем выгрузки плюс каталог батча и отчёт запуска — [03-output.md#layout](./03-output.md#layout).
- Известные конструкции — [05-transform.md#known-constructs](./05-transform.md#known-constructs); для остальных — безопасный fallback.
- Внутренние ссылки `ac:link` + `ri:page`: цель в текущем батче — относительная ссылка на локальный `.md`; иначе — абсолютный `source_url` цели; якорь страницы сохраняется суффиксом `#anchor`, если он известен.
- Локальный однопоточный запуск CLI. Живой Confluence в автоматических тестах не требуется.

## Out of scope

Явно запрещено в первой версии — не реализуется и не появляется во флагах CLI «на будущее».

- Двусторонняя синхронизация и любая запись в Confluence.
- Продуктовый UI, деплой в Docker/Kubernetes/CI, работа как всегда включённый сервис.
- Эмбеддинги, векторная БД, RAG-индекс, чат по выгрузке.
- Рекурсивный обход дерева (descendants), если URL страницы нет во входном списке.
- Комментарии, лайки, restrictions, дамп всех исторических версий страницы.
- Собственный рендер PlantUML или Draw.io в растр.
- Типы контента кроме `page`: blogpost, whiteboard, database и прочие форматы Confluence.
- Confluence Cloud: API, аутентификация Cloud и значение редакции `cloud`.
- Формы URL, не перечисленные в [02-input.md#accepted-url-forms](./02-input.md#accepted-url-forms), в том числе tiny-link `/x/<hash>`.
- Выгрузка тела в `view` / `export_view` / `atlas_doc_format` вместо Storage Format.
- Production-деплой и описание «как катить в кластер» как часть поставки первой версии.

## External constraints

Навязаны платформой, операционной средой или явным внешним выбором. Детали — в модулях конфигурации, выгрузки и оркестрации.

- Конвейер однопоточный: страницы обрабатываются последовательно в одном процессе. Параллелизм страниц и Prefect в текущую поставку не входят.
- Язык — Python `>=3.11,<3.14`. Пакетный менеджер — `uv` + `pyproject.toml`.
- Инстанс — Server/Data Center. База приложения без `/wiki` и без завершающего `/`; контекст-путь, отличный от `/wiki`, допустим.
- Скачивание вложений через браузерный путь `/download/attachments/...` в автоматизации даёт 401; основной путь — REST с тем же Authorization.
- Имена файлов обязаны быть безопасны одновременно для Windows и POSIX. Кириллица в slug страницы недопустима в имени файла Markdown.
- Фикстуры и коммиты не содержат реальных корпоративных страниц, токенов и персональных данных.
- Отдельных правил на содержимое выгрузки (шифровка, маскирование, срок хранения, запрет пространств) нет: тела страниц и вложения пишутся на диск оператора как обычные рабочие файлы.
