# Init Requirements

| Параметр | Значение |
|---|---|
| Продукт | `confluence-md-exporter` |
| Статус | `draft` — ожидает подтверждения человеком |
| Назначение | намерение и внешние ограничения до сборки `docs/spec/` |

Этот файл фиксирует **зачем, для кого, что считается успехом и чего не делаем**. Как устроено внутри — не здесь.

---

## Problem and context

**IR-P-1.** Корпоративная документация живёт в Confluence Server/Data Center. Её нужно регулярно забирать в Markdown-хранилище (Obsidian) и в последующие RAG/LLM-пайплайны.

**IR-P-2.** Штатный экспорт Confluence (PDF, HTML, Word) для этой задачи не годится: теряются макросы, ломаются ссылки на вложения, нет устойчивых идентификаторов и меток, повторный запуск не идемпотентен.

**IR-P-3.** Нужен воспроизводимый, повторяемый, read-only конвейер: список URL страниц на входе; на выходе — Markdown с YAML-метаданными, локальные медиа и машинно-читаемый каталог батча.

---

## Actors and scenarios

**IR-A-1.** Единственный оператор первой версии — инженер на своей машине, с доступом в Confluence. Отдельного сервиса, UI продукта и роли «конечный читатель Confluence» нет.

**IR-A-2.** Основной сценарий: оператор кладёт список URL в входной файл, задаёт доступ к инстансу через окружение, запускает конвейер локально, забирает Markdown, медиа и каталог из выходного каталога.

**IR-A-3.** Повторный запуск на том же списке — штатный режим актуализации, а не исключение. Оператор включает полную перевыгрузку только явно.

**IR-A-4.** Потребители результата (не операторы): Obsidian-хранилище и внешние RAG/LLM-пайплайны. Они читают Markdown, frontmatter, пути к медиа и каталог батча; обратно в Confluence ничего не пишут.

## Goals

Каждая цель опровергается наблюдением на реальном или фикстурном прогоне.

| ID | Цель | Признак успеха |
|---|---|---|
| **IR-G-1** | Выгрузить заданный список страниц `page` из Confluence Server/Data Center | Успешный прогон против DC: для каждой валидной страницы есть Markdown, медиа (если были) и запись в каталоге |
| **IR-G-2** | Сохранить пригодность для Obsidian и RAG | У каждой успешной страницы есть стабильный `id`, `source_url`, labels, путь к `.md` и к каталогу медиа |
| **IR-G-3** | Не портить уже актуальный локальный снимок | Повторный запуск без явной перевыгрузки на неизменённых страницах не перезаписывает актуальные медиа и Markdown |
| **IR-G-4** | Изолировать ошибки по страницам | Страница с 403, 404 или битым телом не останавливает остальные; причина видна в отчёте запуска |
| **IR-G-5** | Не терять неизвестные макросы молча и не валить из‑за них батч | Неизвестный макрос оставляет в теле след с именем макроса и извлечённым текстом; страница не переходит в failed только из‑за этого |
| **IR-G-6** | Дать оператору сводку в Prefect UI | На успешную страницу есть markdown-артефакт с превью; на запуск — сводка |

## Non-goals

Сознательно не делаем в первой версии. Это не «остаток», а отказ.

**IR-NG-1.** Двусторонняя синхронизация и любая запись в Confluence.

**IR-NG-2.** Продуктовый UI, деплой в Docker/Kubernetes/CI, работа как всегда включённый сервис.

**IR-NG-3.** Эмбеддинги, векторная БД, RAG-индекс, чат по выгрузке.

**IR-NG-4.** Рекурсивный обход дерева (descendants), если URL страницы нет во входном списке.

**IR-NG-5.** Комментарии, лайки, restrictions, дамп всех исторических версий страницы.

**IR-NG-6.** Собственный рендер PlantUML или Draw.io в растр.

**IR-NG-7.** Типы контента кроме `page`: blogpost, whiteboard, database и прочие форматы Confluence.

**IR-NG-8.** Confluence Cloud: API, аутентификация Cloud и значение редакции `cloud`.

## In scope / out of scope

### In scope

Первая версия обязана уметь ровно это.

**IR-IN-1.** Только Confluence Server/Data Center.

**IR-IN-2.** Только страницы типа `page`.

**IR-IN-3.** Единственный вход — текстовый список URL (пустые строки и `#`-комментарии игнорируются). Допустимые формы после нормализации base:

- `.../pages/viewpage.action?pageId=<id>`
- то же с дополнительными query-параметрами (`src=` и аналоги)
- `.../display/SPACE/Page+Title`
- `.../wiki/spaces/SPACE/pages/<id>/Title`
- `.../wiki/spaces/~user/pages/<id>/Title`
- голая числовая строка `pageId` (только цифры)

Дубликаты URL/`pageId` схлопываются с предупреждением в лог. Строка, которая не распознана, не валит батч: она попадает в отчёт запуска как невалидная.

**IR-IN-4.** Выгрузка metadata + тела в Storage Format, вложений и встроенных медиа, нормализация макросов `ac:*` / `ri:*`, сборка GFM Markdown с YAML frontmatter.

**IR-IN-5.** Четыре выходных слоя под корнем выгрузки плюс каталог батча и отчёт запуска — состав слоёв задан в **IR-D-2** (навязанный контракт выгрузки, не внутренний дизайн кода).

**IR-IN-6.** Макросы и конструкции из **IR-D-5** плюс безопасный fallback для всех остальных (**IR-D-6**).

**IR-IN-7.** Локальный запуск Prefect 3.x flow (прямой вызов flow / `prefect flow run` / эквивалентный CLI-вход). Живой Confluence в автоматических тестах не требуется: достаточно фикстур XML/JSON.

**IR-IN-8.** Внутренние ссылки `ac:link` + `ri:page`: если цель входит в текущий батч — относительная ссылка на локальный `.md`; иначе — абсолютный `source_url` цели. Якорь страницы сохраняется суффиксом `#anchor`, если он известен.

### Out of scope

Явно запрещено в первой версии — не реализуется, не появляется во флагах CLI «на будущее».

**IR-OUT-1.** Всё из раздела Non-goals.

**IR-OUT-2.** Формы URL, не перечисленные в **IR-IN-3** (в том числе tiny-link `/x/<hash>`).

**IR-OUT-3.** Выгрузка тела в `view` / `export_view` / `atlas_doc_format` вместо Storage Format.

**IR-OUT-4.** Production-деплой и описание «как катить в кластер» как часть поставки первой версии. Достаточно способа запустить локально.

**IR-OUT-5.** Confluence Cloud (**IR-NG-8**).

## External constraints

Пункты ниже навязаны платформой, операционной средой или явным внешним выбором. Это не решения по внутреннему устройству.

**IR-X-1.** Оркестратор — Prefect 3.x (`prefect>=3,<4`). Кэш Prefect не считается идемпотентностью на диске: пропуск повторной выгрузки обязан смотреть на локальные файлы и версию страницы в Confluence.

**IR-X-2.** Язык реализации — Python `>=3.11,<3.14`. Пакетный менеджер — `uv` + `pyproject.toml`.

**IR-X-3.** Инстанс — Server/Data Center. Origin задаётся без хвоста `/wiki` и без завершающего `/`. Тип аутентификации задаётся явно (`basic` \| `bearer`). Значение редакции `cloud` — ошибка конфигурации (невозможный старт).

**IR-X-4.** Режимы аутентификации первой версии:

- Server/DC BEARER: PAT;
- Server/DC BASIC: username + password/token.

Файл `.env` с кредами не коммитится; пример ключей поставляется отдельно. Отдельных правил на содержимое выгрузки (шифровка, маскирование, срок хранения, запрет пространств) нет: тела страниц и вложения пишутся на диск оператора как обычные рабочие файлы.

**IR-X-5.** Скачивание вложений через браузерный путь `/download/attachments/...` в автоматизации даёт 401. Основной путь — REST с тем же Authorization, с follow redirects, без cookie-сессии.

**IR-X-6.** HTTP: синхронный клиент на весь конвейер (async не требуется). Таймаут, SSL verify (по умолчанию включён), ретраи на 429/502/503/504 с уважением к `Retry-After`. 403 не ретраить бесконечно.

**IR-X-7.** Имена файлов обязаны быть безопасны одновременно для Windows и POSIX. Кириллица в slug страницы недопустима в имени файла Markdown.

**IR-X-8.** Фикстуры и коммиты не содержат реальных корпоративных страниц, токенов и персональных данных.

**IR-X-9.** Ключи окружения первой версии (имена стабильны; семантика — контракт запуска, не схема кода):

| Ключ | Обязательность | Смысл |
|---|---|---|
| `CONFLUENCE_BASE_URL` | да | origin инстанса |
| `CONFLUENCE_EDITION` | нет, default `datacenter` | единственное допустимое значение `datacenter`; иное — код выхода `2` |
| `CONFLUENCE_AUTH_TYPE` | да | `basic` \| `bearer` |
| `CONFLUENCE_TOKEN` | да | PAT или password |
| `CONFLUENCE_USERNAME` | да, если `basic` | username DC |
| `CONFLUENCE_VERIFY_SSL` | нет, default `true` | проверка TLS |
| `CONFLUENCE_TIMEOUT_SECONDS` | нет, default `30` | HTTP timeout |
| `CONFLUENCE_MAX_RETRIES` | нет, default `3` | ретраи на 429/5xx |
| `EXPORT_OUTPUT_DIR` | нет, default `data` | корень слоёв |
| `EXPORT_INPUT_FILE` | нет, default `input/urls.txt` | входной список |
| `EXPORT_CONCURRENCY` | нет, default `2` | параллелизм страниц |
| `EXPORT_FORCE_REFRESH` | нет, default `false` | игнорировать disk-skip |
| `LOG_LEVEL` | нет, default `INFO` | |

**IR-X-10.** CLI первой версии принимает как минимум входной файл, выходной корень и флаг полной перевыгрузки. Коды выхода: `0` — все страницы ok или skipped; `1` — частичный failure; `2` — конфигурация / auth / невозможный старт.

## Data and result expectations

### Вход

**IR-D-1.** Файл `input/urls.txt` (путь переопределяется `EXPORT_INPUT_FILE`): UTF-8, одна запись на строку. Правила разбора — **IR-IN-3**.

### Выходной layout (навязан)

**IR-D-2.** Корень `EXPORT_OUTPUT_DIR` (default `data`):

```text
data/
├── 01_raw/<page_id>.json
├── 02_interim/<page_id>.html
├── 03_assets/<page_id>/<safe_filename>
├── 04_markdown/<page_id>_<slug>.md
├── 04_markdown/manifest.json
└── run_report.json
```

Каноническая относительная ссылка на медиа из Markdown:

```text
../03_assets/<page_id>/<safe_filename>
```

Другая схема путей (`../assets/...` и аналоги) запрещена: из каталога `04_markdown/` она не резолвится в `03_assets/`.

### Bronze

**IR-D-3.** `01_raw/<page_id>.json` хранит как минимум: `page_id`, `edition`, `title`, `space_key`, `version`, `status`, `created_by`, `updated_at`, `source_url`, `labels`, `ancestors` (id + title), `body_storage` (именно Storage Format), список вложений (`id`, `title`, `media_type`, `file_size`, путь скачивания через REST), `fetched_at`. Поля можно расширять, перечисленные ключи стабильны. `page_id` везде строка.

Для вложений с небезопасным исходным именем ведётся карта `original → safe` рядом с raw (sidecar); в Markdown попадают только безопасные имена.

### Gold Markdown

**IR-D-4.** Обязательные ключи YAML frontmatter: `id` (строка), `title`, `space_key`, `version`, `status`, `created_by`, `updated_at`, `source_url`, `labels`, `breadcrumbs` (titles предков + текущий title), `attachments_count`, `unsupported_macros`. Тело — GFM.

**IR-D-5.** Ожидаемый вид известных конструкций (что видит читатель Markdown, не как это разбирается внутри):

| Источник | Результат |
|---|---|
| Обычный HTML `p,h1-h6,ul,ol,li,table,thead,tbody,tr,th,td,em,strong,code,pre,br,hr,a` | GFM / ATX / pipe-tables |
| Макрос `code` | fenced-блок; язык из параметра, иначе `text` |
| `plantuml` / `plantumlcloud` | fenced `plantuml`; картинка не рендерится |
| `drawio` / `draw.io` | ссылка на preview png/svg среди вложений, если есть; если есть исходник `.drawio`/`.xml` — вторая ссылка `[source](...)` |
| `info`, `note`, `panel` | `> [!NOTE]` |
| `warning`, `error` | `> [!WARNING]` |
| `tip`, `success` | `> [!TIP]` |
| `ac:image` + вложение | локальная картинка по каноническому относительному пути |
| `ac:image` + внешний URL | внешний URL без переписывания |
| вложение в ссылке | локальная файловая ссылка |
| `expand` | `<details><summary>…</summary>…</details>` |
| `status` | код-спаны с текстом статуса; цвет в MVP игнорировать |
| task list | `- [x]` / `- [ ]` |
| emoticon | короткий текстовый эквивалент |
| ссылка на пользователя | `@displayName` или `@accountId` |
| дата/time | ISO-дата текстом |

**IR-D-6.** Неизвестный макрос: HTML-комментарий `<!-- unsupported-macro: <name> -->`, сохранённый текст содержимого, имя в `unsupported_macros`. Пайплайн из‑за этого не падает.

**IR-D-7.** Краевые случаи, которые обязаны не валить страницу в неопределённое состояние: пустое тело; макрос без body; тройные бэктики внутри code-блока; два вложения с одним именем разных версий — брать current; вложение с другой страницы (скачать, если доступно, иначе placeholder и предупреждение); таблица с colspan — упростить до GFM без объединения ячеек; HTML-entities в title; `trashed` или 404 — запись в отчёт и skip; 403 — запись `forbidden` без бесконечных ретраев.

**IR-D-8.** `slug` страницы: нижний регистр, NFKC, пробелы и пунктуация → `-`, алфавит `[a-z0-9-]`, кириллица транслитерируется, обрезка до 60 символов, пустой slug → `page`. Конкретный алгоритм транслитерации продуктовым ограничением не является: спека выбирает один общепринятый и фиксирует его.

**IR-D-9.** `manifest.json` — массив записей: `id`, `title`, `space_key`, `version`, `source_url`, `md_path`, `assets_dir`, `labels`, `status` (`ok` \| `failed` \| `skipped`), `error` (nullable). Невалидные URL в манифест не входят.

**IR-D-10.** `run_report.json`: `started_at`, `finished_at`, `pages_total`, `ok`, `failed`, `skipped`, `invalid_urls`, `force_refresh`, список ошибок по `page_id`.

**IR-D-11.** Disk-skip (когда `EXPORT_FORCE_REFRESH=false` и raw уже есть): достаточно сравнить `version` страницы на сервере с локальным raw. Если версия совпала и локальные ассеты на месте с тем же size — не перезаписывать raw и не качать вложения заново. Пробы через ETag и прочие заголовки не требуются.

**IR-D-12.** Изоляция: весь батч не падает из‑за одной страницы. Запуск успешен, если есть хотя бы одна страница `ok`; если все failed — запуск failed. Как именно это выражено в Prefect (task / subflow / перехват) — не здесь.

## Product acceptance

Человек считает первую версию сделанной, если одновременно верно:

**IR-ACC-1.** Все цели **IR-G-1**–**IR-G-6** наблюдаются на прогоне.

**IR-ACC-2.** Прогон по фикстурам без сети покрывает каждый URL-паттерн из **IR-IN-3** и каждую конструкцию из **IR-D-5**, плюс fallback **IR-D-6** и краевые случаи **IR-D-7**.

**IR-ACC-3.** Все ссылки `../03_assets/...` в сгенерированных Markdown резолвятся в существующий файл.

**IR-ACC-4.** Повторный прогон без force-refresh на неизменённых страницах даёт `skipped` и не меняет байты актуальных файлов в `03_assets/` и `04_markdown/`.

**IR-ACC-5.** Out of scope из **IR-OUT-*** и Non-goals не появляется в CLI, выходных контрактах и тестах первой версии.

**IR-ACC-6.** Файлы кредов и токены не коммитятся и не кладутся в фикстуры. Содержимое страниц на диске оператора и в Prefect preview не маскируется.
